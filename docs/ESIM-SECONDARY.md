# 第二只 DJI 模块：eSIM 与短信

第二只 DJI 一代模块在 KK-Car 中是**通信副卡**。它只通过 USB 串口访问 9eSIM 卡与短信，不加入 WAN、VPN、PBR 或流量统计，不启动移动数据拨号。主 DJI QMI 模块仍独自承担 4G 上网。当前只识别已确认的副卡 USB 产品标识；若模块型号或固件变化，先重新核对标识，不要放宽为「任意 ttyUSB」。

## 页面操作

用原 OpenWrt 管理员登录，打开左侧「副卡与 eSIM」，也可直接访问 `/cgi-bin/luci/admin/kkcar_esim`。页面显示第二只模块是否识别、是否出现数据接口、SIM 短信仓位、卡内配置名称与标识尾四位、当前启用状态、自动轮换设置，以及副卡短信目录和加密历史。完整 EID/ICCID 不在页面、公开源码或日志中展示。

- **短信**：进入页面后自动读取卡内列表，选择项目可读正文；可输入号码和不超过 70 字的正文，由副卡发送。实际发送可能收费，提交结果不明确时先检查收件方，避免重复发送。
- **自动归档**：后台约每分钟读取副卡目录；新完整短信先做两份加密归档，其中一份可供设备本地管理员查看。若通知中心已启用短信与飞书目标，才按现有设置发送正文；只有归档、历史和当时应投递的目标均验证成功后，才清理对应新短信的卡内片段。旧短信、缺段短信及不确定结果不自动删除。副卡在配置切换后看到的旧短信先作为基线，不误报为新消息。
- **切卡**：可以手动启用卡内已有配置；后台核对启用状态，失败时尝试恢复原配置。勾选至少两份配置、设定 30–1440 分钟间隔后，才能开启自动轮换。当前只有一份配置，按钮保持关闭且后台也拒绝切换。此功能**不下载、删除或停用 eSIM 配置**。

自动轮换适合定时查看不同号码的短信，但切卡会使当前号码暂时离线，也可能受运营商注册时间影响。建议先用两张非关键配置做现场切换和复网测试，再启用无人值守。9eSIM B1 的蓝牙写卡仍由其独立管理工具完成；本页面管理已在卡内的配置，不提供远程下载新配置。

## 数据费用保护

副卡绑定脚本仅加载串口驱动，不注册网络驱动、不配置 PDP 数据连接，也不修改网络或 VPN 配置；守护服务如果发现属于副卡 USB 设备的网络接口，会将其置为 down。页面上的「移动数据未建立」来自设备实际接口检测。更换固件、开启 ECM 模式或新增驱动后，必须再次核实没有副卡数据接口和默认路由；**不要将副卡接口手动加入 WAN**。短信收发可能产生运营商短信费用，但不应使用其移动数据套餐。

## 部署与恢复

设备运行 OpenWrt 25.12 系列，先从该固件匹配的软件源安装官方 `lpac`、Python 3、`ucode`、OpenSSL 与已有的 LuCI/rpcd 依赖。只迁移本项目所需文件，不复制开发目录内的私有数据。启用 `kk-car-esim` 服务，重新加载 `rpcd`，再清除 LuCI 菜单缓存或刷新页面。旧网络服务无须重启。`esim_bridge.py` 只对模块拒绝的 `AT+CCHC=?` 可选能力探测做代理，其余真实卡命令转发到模块；当前设备已通过只读配置列表验证。

重刷或换 SD 卡时，除原有短信密钥外，还要离线备份 `/etc/kk-car/private/esim-secondary.json`、`esim-sms-forward-state.json`、`esim-sms-history/`、`esim-sms-history-index.json`、`esim-sms-seen.json` 及既有短信证书/密钥。这些资料包含配置选择或敏感短信，不上传公开仓库。停止副卡服务可用 `/etc/init.d/kk-car-esim stop`；不要通过删除卡内配置排障。

## 当前验证边界

实机已读到一份启用配置，副卡无网络接口，主卡 QMI WAN 仍在线；页面和自动轮换设置的保存/回读已验收，自动轮换默认关闭。一条外部测试短信已进入副卡，生成设备本地加密历史，飞书接口返回成功，卡内仓位在核验后清空；尚待用户确认飞书客户端实际收到。由于卡内只有一份配置，**实际切卡、切换后复网与副卡发短信仍未验收**。这些能力必须在条件具备时分别做现场测试。
