# OpenVPN/TCP 与 WireGuard 自动选线

KK-Car 同时保持两条公司 VPN 隧道待命。物理上联从断线恢复或在有线 WAN、4G 之间切换后，选择器立即比较；平时每 5 分钟比较一次。比较目标为公司内网探测地址，分别强制绑定 `ovpncar` 和 `wgcar`，不会把探测包回落到物理 WAN。

每条隧道每轮发 5 个 Ping，至少收到 4 个才视为健康；用往返时间的中位数作为延迟，并对丢包加惩罚。只有候选线路比当前线路快 **至少 10 ms 且至少 15%**，连续两轮成立，并且距上次切换已满 10 分钟时才切换。网络恢复后的首次比较可直接选择明显更快的健康线路；当前线路不健康且另一条健康时立即切换。两条都不健康时保持当前选择，由防直连规则阻断经 VPN 的业务，不放行到物理 WAN。测得的低延迟只是当次路径表现，不保证移动途中每时每刻更快。

切换同时更新 PBR 的公司/国际业务与国外 DNS 策略、表 300 的隧道默认路由，以及 DNS 上游的接口绑定；选中线路必须再次通过真实路由与 Ping 验证，否则回到原线路。旧线路保持在线，以便快速回切。两条隧道的管理地址分别有独立回程表，回复不会从另一条 VPN 或物理 WAN 发出。已有的 TCP 会话在切换时可能中断并重连；没有做多路聚合或零中断迁移。

管理页显示当前协议及两条隧道最近一次探测的中位延迟。每 10 秒的实时延迟和历史曲线只记录**当前选中的 VPN**，并标明接口。网页的“暂停 VPN”会停止两条隧道并暂停选择器；“启动 VPN”恢复两条。开机自动连接开关同时控制 OpenVPN、WireGuard 和选择器的开机状态。网络守护按当前选中的协议执行恢复操作。

## 部署与恢复

这套逻辑针对现有 `ovpncar`、`wgcar`、PBR、DNS 与防火墙配置。新设备不可直接覆盖配置。部署前备份 `/etc/config/{pbr,dhcp,network,firewall}` 和原脚本，并验证两条隧道单独绑定接口时都能到达公司探测服务及所需国际出口。PBR 需同时支持 `ovpncar`、`wgcar`，WireGuard 不得在 ignored list；两条隧道需处于相应防火墙区并允许 LAN 转发。

服务为 `/etc/init.d/kk-car-vpn-select`，选择状态仅存 `/tmp/kk-car-vpn-select.json`。若需临时回到已验证的 OpenVPN 路线，先停用选择器，再将 `pbr.kk_global.interface` 和 `pbr.kk_dns.interface` 改回 `ovpncar`，恢复国外 DNS 的 `@ovpncar` 绑定，重启 PBR 与 dnsmasq，并运行 `/etc/kk-car/ike-route-ensure.sh`。核对表 300 默认路由为 `ovpncar`、不可达兜底仍存在，并从 LAN 客户端复测公司、国内和国外地址。不要只停用 `wgcar` 而保留指向它的 PBR 与 DNS 配置。

## 本轮验证边界

2026-10-07 在当前 4G 上，两条隧道分别强制绑定接口到公司探测地址，5 次探测均成功；WireGuard 约 60–82 ms，OpenVPN/TCP 约 56–135 ms。实际切到 WireGuard 后，PBR 两项、DNS 绑定、表 300 路由读回一致，公司 HTTP、国外 HTTPS 与国外 DNS 解析可用；后台、实时 Ping 与管理回程路由读回正常。自动决策测试覆盖明显更快、小差距、丢包、滞留时间和当前线路失效。**尚未通过真实断开上联、移动中长时间运行或有线 WAN 重测**，因此不能承诺无感切换或始终选择绝对最低延迟。
