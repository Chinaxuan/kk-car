# 飞书事件推送

2026-09-20 新增。首页右上角「飞书推送」进入设置，也可打开 `/cgi-bin/luci/admin/kkcar_notifications`。后台持续运行，关闭浏览器仍会检测。

## 日常设置

1. 打开总开关，在一个推送地址中填写飞书自定义机器人 Webhook，并勾选「启用此地址」。
2. 选择要接收的通知、调整阈值，点击「保存推送设置」。通常在下一轮约 5 秒的采样中生效；有发送请求正在执行时可能稍后生效。
3. 点击「发送测试通知」，在下方查看每个地址的接收结果。测试按钮使用**已保存**设置，每分钟最多一次。

最多支持三个地址，独立命名和启停，启用的地址接收相同事件。地址不会回显；留空保留原值，勾选「清除已存地址」并保存才删除。关闭总开关时测试也不会发送。页面展示飞书已接收，不代表群内成员已阅读。

## 事件与默认规则

| 通知 | 判定 | 默认 |
| --- | --- | --- |
| VPN 上线 / 下线 | IKEv2 已建立且 CHILD SA 已安装的状态改变，确认约 10 秒 | 启用，分别控制 |
| 开机 | 持久化启动 ID 改变；初次安装服务不伪装成开机 | 启用 |
| 正常关机 / 重启 | rc.common 的 shutdown 钩子，优先发送此事件 | 启用 |
| 异常断电后启动 | 新启动发现上次没有正常关机标记，提示可能断电、崩溃或钩子未执行 | 启用 |
| 设备接入 | 已授权 Wi-Fi 关联，或 br-lan 上 REACHABLE/DELAY/PROBE 邻居记录；初次采样只建立基线 | 启用 |
| 设备离线 | 已见设备连续约 120 秒未再出现 | 默认关闭，可启用 |
| 上网出口变化 | 有线、4G、无可用出口之间的变化，确认约 10 秒 | 启用 |
| VPN 延迟过高 | 平均延迟 ≥300 ms，持续 30 秒；低于阈值 80% 后确认恢复 | 启用 |
| VPN 丢包 | 丢包 ≥50%，持续 30 秒；低于阈值一半后确认恢复 | 启用 |
| 蜂窝弱信号 | LTE RSRP ≤−115 dBm，持续至少 60 秒；回升 5 dB 后确认恢复 | 启用 |
| 树莓派欠压 | 当前欠压位持续约 10 秒，历史欠压位不触发 | 启用 |
| 高温 | ≥80°C，持续 30 秒；下降 5°C 后确认恢复 | 启用 |
| 异常恢复 | 延迟、丢包、信号、供电、温度恢复通知 | 启用，可统一关闭 |
| DJI 新短信正文 | 后台每约 30 秒读模块目录，长短信收齐后才向已启用地址发送号码、时间和正文 | 默认关闭；本机可按页面单独开启 |
| DJI SIM 来电 | 模块报告语音来电振铃时发送一次文字提醒，不附来电号码 | 启用，可单独关闭 |
| DJI SIM 未接来电 | 已看到振铃，随后归于空闲且未记录网页接听时发送 | 启用，可单独关闭；短通话及跨采样状态可能无法准确分类 |

页面可以修改六项阈值。状态采样间隔约 5 秒，发送请求会增加一轮的耗时；短于采样间隔的来电可能漏报。异常数据未知或过期时不伪造正常/异常；监控长时间中断会重置持续判定。同类同方向事件默认至少相隔 300 秒，恢复方向单独计时。持续同一个状态不会周期刷屏。阈值、地址或开关保存后重新建立判定基线，并清除旧待发队列，避免旧事件发送给新地址。

## 断网、断电与边界

短信转发由独立的 `kk-car-dji-sms-forward` 服务执行，复用这里的总开关、短信事件开关和三个地址的独立开关。首次运行以及切换 `ME`/`SM` 存储仓时只建立已有短信基线，不把历史验证码整批推送到群；此后按完整短信与地址分别记录投递。新短信正文不会进入普通事件队列或最近成功日志。失败时每约 30 秒重试，前提是原件仍在当前短信仓；飞书已收而回复丢失时仍可能重复。当前新短信原件存入 SIM `SM`，并在树莓派在线时加密归档到 SD 卡。SIM 存储满时，新短信可能根本无法到达，转发服务不能代替清理和备份。

- **突然断电不能即时推送**。需要独立常在线服务器或带后备电源的设备，才能在树莓派掉电时立即报告；本版本在下次启动后提示异常关机记录。
- 正常关机发送是尽力而为，要求当时还有网络。每个地址连接超时 4 秒、总超时 8 秒，不因推送无限阻塞关机。安装后没有为测试而真实断电或重启设备。
- 失败消息保存在内存队列中，最多 50 条、最长 1 小时；批量最多 10 条/请求，失败退避 60–300 秒。一个地址成功后不因另一个地址失败而重复发送给已成功地址。
- 超过队列上限丢弃最早消息；重启会丢失 RAM 待发消息。关闭开关/地址、换配置会取消待发消息，不在重新启用时补发全部历史。
- 网络超时可能发生在飞书已收消息但返回包丢失之后，重试存在重复消息可能，不承诺严格恰好一次。
- VPN 上线不等于国外业务可用；延迟/丢包检测仍使用既有 `10.8.8.8` 经 VPN 探测缓存。
- 有线设备采用邻居记录被动发现，没有主动扫描；静默终端的接入可能漏报或延后，MAC 随机化可能识别为新设备。Wi-Fi 采样使用当前设备的 `hostapd.phy0-ap0`。
- 目前支持飞书自定义机器人普通文本 Webhook；没有实现额外签名密钥。机器人若启用签名校验，会在发送结果中显示飞书业务错误，需要另行适配。可按需要配置包含 `KK-Car` 的关键词策略。

## 私密配置与实现

- `/etc/kk-car/private/notify.json`：地址、开关、阈值；目录 0700，配置 0600，保存时原子替换。
- `/etc/kk-car/private/notify-boot.json`：启动 ID 与正常关机标记；每次启动/关机写一次，不高频写卡。
- `/tmp/kk-car-notify-*`：状态、队列、测试请求；日志不记录 Webhook。
- `/tmp/kk-car-voice-answered`：网页接听成功后的临时无号码标记，用于避免把短暂接通误判成未接；在通话结束判定后清理。
- `/etc/kk-car/private/dji-sms-forward-state.json`：短信指纹和投递标记，不保存号码或正文；`sms-archive/` 保存公钥加密的短信副本，私钥不放在设备上。
- `/tmp/kk-car-sms-forward*`：短信转发临时请求与状态；正文仅短暂写入 root 可读的内存盘文件，完成后移除。
- `notify-config.uc`：校验、私密存储、对页面返回无地址的摘要。
- `notify-engine.uc`：纯状态变化和防抖逻辑，可用隔离时间序列测试。
- `notify-worker.uc` / `notify-watch.sh` / `kk-car-notify`：采样、队列、发送、开关机钩子。
- LuCI `notify_get` 为读权限；`notify_save` / `notify_test` 为写权限，沿用原管理登录。

只允许 `https://open.feishu.cn/open-apis/bot/v2/hook/UUID`，拒绝其他主机、HTTP、控制字符、任意路径和 URL 参数。curl 开启正常 TLS 校验、不跟随重定向，URL 放在受限临时配置文件，不出现在 curl 命令行。HTTP 200 且飞书返回业务码 0 才记录接收成功。普通事件消息包含事件、时间、必要设备名称和 MAC 后缀；来电提醒不含电话号码。不会发送公网 IP、VPN 服务器地址或密钥。飞书自定义机器人只能发文字提醒，不能直接转接 SIM 语音。

私密配置、实际 Webhook、启动标记和运行队列都不进入 GitHub。项目只保存实现和说明。接口格式参考：[飞书官方自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。
