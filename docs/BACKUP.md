# 备份与恢复

## 两份备份分别解决什么

| 备份 | 内容 | 保存位置 |
| --- | --- | --- |
| GitHub 项目仓库 | 源码、服务、静态规则、产品设计与使用说明 | 本公开脱敏仓库 |
| 设备配置备份 | 实际网络配置、PSK、管理员凭据等设备私密数据 | 自己的离线安全存储，禁止提交 Git |
| DJI 短信加密备份 | 号码、正文及分段信息的密文 | 设备 SD 卡私有目录和独立离线副本；解密私钥仅在设备之外 |
| DJI 流量校正记录 | 今日/月度网卡累计、运营商报告解析值与查询设置 | 设备 `/etc/kk-car/private/dji-traffic-*.json`；可随加密设备配置备份保存，不上传公开仓库 |
| DJI 通话记录与联系人 | 新通话的方向、时间、已接时长、号码和管理员手动保存的联系人 | 设备 `/etc/kk-car/private/dji-phonebook.json`，权限 0600；需随私密配置单独加密备份，不上传公开仓库 |

源码与配置缺一不可。OpenWrt 配置备份不是完整 SD 卡镜像，重刷后还要安装匹配的软件包。

流量统计文件只存解析后的数字，不存短信正文；重刷或恢复旧备份后，今日/月度用量可能从旧采样点继续，首次网卡采样会建立新基线。套餐数字应再次以运营商短信核对，不能把恢复的旧余额当作当前账单。

通话记录最多保留最近 100 条、联系人最多 100 位；新通话由树莓派约每 5 秒观察模块语音状态，结束时写入私有文件，断电前尚未观察到结束的通话可能留下未完成状态。该文件未加密，离线备份时应由备份介质或加密容器保护。GitHub 只保存记录逻辑，不保存真实号码或历史。

当前 DJI 新短信原件优先保存在 SIM `SM`，容量 40 条；树莓派运行并连接模块时，将完整短信按会话用 CMS/AES-256 加密至 `/etc/kk-car/private/sms-archive/*.der`。路由器只保存公开证书 `/etc/kk-car/private/sms-archive-recipient.pem`，解密私钥绝不上传 GitHub 或复制到路由器。2026-09-24 清理前，模块 `ME` 的 23 个片段（含一条缺片会话）与 SIM `SM` 的 40 个片段分别制成全量加密快照，在 Mac 解密核验并复制到 SD 卡比对 SHA-256。清理时新收到的过渡短信也已单独加密归档。要恢复内容，需从离线安全位置取回对应私钥，在可信电脑上用 `openssl cms -decrypt -binary -inform DER -in <备份.der> -recip <公开证书.pem> -inkey <私钥.key>` 解密。解密输出含验证码和号码，切勿上传或粘贴到聊天中。丢失私钥就无法恢复密文，请另存一份离线副本。SD 卡扩容不会增加 SIM 或模块短信仓容量。

16GB SD 卡使用 OpenWrt squashfs 镜像时，初始 `p2` 只有约 104MB，其中可写 overlay 约 86MB；页面若看到只读 `/rom` 100%，不代表卡坏。实机已保留修改前前 180MiB 的离线镜像，原位扩展 `p2` 并在线扩大 `/dev/loop0` ext4 overlay；当前 `df` 显示根可写区 14.0GB、空闲约 13.3GB。整个过程未改 boot 分区或网络配置。以后重刷小镜像或某些系统升级后，应重新核对分区和 overlay 容量；不能假设 16GB 会自动全部可用。扩容或重刷前保持稳定供电并保存最新配置、短信密文与私钥。

本仓库不包含管理员或热点密码、VPN PSK、SSH 私钥、WireGuard 密钥、实际 UCI 配置、抓包或历史记录。`.gitignore` 是辅助防误提交措施，不能代替发布前检查。请勿将父目录的 `work/`、`private/`、`outputs/` 整体拖入 GitHub。

## 设备损坏或换卡

1. 准备适合树莓派 3B+ 的 OpenWrt 镜像并刷卡，先验证稳定供电与本地管理。
2. 安装匹配固件的软件包，参考 `packages-reference.txt`。
3. 使用离线配置备份恢复网络和 VPN 凭据；若没有配置备份，需要重新填写双方认证资料。
4. 按 [部署说明](DEPLOYMENT.md) 恢复自定义脚本、面板、服务与启动项。
5. 按 LAN → 4G → Wi-Fi → VPN → 分流 → DNS → 面板顺序验证。
6. 确认 IPv6、VPN 断线保护、热点/网口回退和历史写入后，再用于行车。

## 更新失败时回退

保留最近一次确认可用的离线配置包以及对应源码版本。只有页面问题时优先恢复 CSS/JS；后台问题恢复对应脚本与服务。不要先删除路由服务：保留的不可达路由可能使网络无法恢复。

完整撤销有线 WAN 功能时，先恢复 LAN，再按架构清理 table 301 的规则和优先路由；不熟悉路由时使用维护前完整备份恢复。

## 后续 Git 备份

此仓库记录一次明确的基线版本。后续调整建议将源码和说明一并更新，提交前检查差异和暂存区；禁止加入密钥、整机配置压缩包和运行时历史。

历史数据约每 5 分钟保存，突然断电可能损失最近约 6 分钟。若需要历史本身的备份，应单独离线保存 `/etc/kk-car/history/`。

## 飞书推送的私密资料

`/etc/kk-car/private/notify.json` 含实际机器人 Webhook，不上传到仓库，也不应粘贴到 Issue。需要迁移时离线妥善备份，并恢复 0700 目录 / 0600 文件权限。丢失该配置后可以在页面重新填写地址。运行队列在 RAM 中，重启后不会恢复；启动标记没有重建网络所需的认证资料。


## HDMI 本地状态屏

可选的 `kk-car-hdmi` 服务直接输出到树莓派 HDMI；安装前备份启动配置，停止服务可恢复文本控制台。显示模式、安装、检查与撤销步骤见 [HDMI 状态屏](HDMI.md)。原设备启动配置与画面截图只保留在私密备份中。

## VPN 备用管理与无线修复的回退资料

实施前离线保留 firewall、wireless 与 ike-route-ensure.sh。VPN 返回路由的运行状态位于 `/tmp/kk-car-vpn-management-sources`，由守护按实际地址重建，不应当作固定地址配置恢复。停用方法、无线回退和本地故障分层排查见 [网络恢复](NETWORK-RECOVERY.md)。


UPS 空电/保护参数修改前的寄存器和模式快照只保存在设备 `/etc/kk-car/private/` 与本地私有目录。恢复时保持外部供电，逐项回读；不要把保护值 0 当成关闭保护，也不要直接刷入其他板子的加密固件。彻底断电后参数保留尚未验证，详见 [UPS 电源](UPS.md)。这些快照与固件包不进入公开备份。
