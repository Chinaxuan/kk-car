# 验证与限制

基线时间：2026-09-19。以下为项目开发过程中已取得的验证记录，不能推断所有未来环境都相同。

## 已在真实设备验证

- F30A Pro USB 上网、5 GHz / 20 MHz 热点、LuCI 登录与权限。
- 国内、国外、公司内网、DNS 的实际访问；VPN 停止后国外业务不直出，恢复后可重新访问。
- 页面热点及网口控制的持久化读回；真实 LAN → WAN → LAN 操作，未接有线上级时保留 4G。
- IPv6 内核开关、地址和路由检查；接口重载后仍关闭。
- ADB 断开后重新连接、状态缓存过期处理。
- Ping 与信号历史采集、保存、读取；1 小时 / 30 天图表。
- ChatGPT 边缘地区与 Gemini 页面地区各返回 JP，HTTP 200；这只是当时的网络地区观测。
- Chrome 1800×863 一屏显示；已有手机适配验证记录。

## 隔离测试

`kk-car-ui/tests/` 提供热点与网口事务、路由选网、Ping 解析、历史聚合及 AI 地区解析测试。路由器测试在临时目录运行隔离夹具，不替换真实网络配置；`uplink-routing.py` 需要具备网络命名空间能力的 Linux 环境。

- 超时回退、确认保留、开机恢复、任务锁和非法输入。
- 真实 Linux 网络命名空间内的有线优先、防抖、失败回退、网段冲突及无出口阻断。
- 延迟/速率加权、丢包、重启恢复、损坏尾行、旧新信号格式兼容与重复/过期信号排除。
- 30 天 43201 分钟夹具汇总；不是等候 30 天实地记录。
- AI 地区 20 项测试：CN、非 CN、未知、403/429、超时、超大响应、失效格式、页面语言与无关国家文本误判。

现有测试脚本默认从仓库根目录的 `work/private/pi-admin` 与 `work/pi-reflash-known-hosts` 获取本地 SSH 凭据。它们故意不在仓库中；运行前自行准备自己的授权密钥或修改测试连接配置。测试路径仍以 `kk-car-ui/` 为项目子目录。

## 尚未验收或已知限制

- 没有长时间行车、跨基站、多个运营商或多 USB 上网棒切换验收。
- 真实有线 WAN 下的 IKEv2 尚未验证，模拟测试不能代替实机验收。
- 没有完成空白 SD 卡一键重建或整机冷启动验收。
- 曾持续检测到欠压和降频，网络检查通过不能证明供电已恢复正常。
- 不保证网络切换时 TCP 会话无中断，也不叠加多线路带宽。
- 5 GHz / 2.4 GHz 不能同时运行；页面的固定信道策略依赖当前设备环境。
- Gemini 页面内部字段可能改变；地区未知不代表 CN，非 CN 也不代表账号可用。
- 中国 IP 集合为静态快照，更新原始网段时需同步重建 nftables 集合；域名分流数据与设备配置需另行恢复。
- 本版本为单设备定制，接口名、内网目标与部分服务端地址仍需迁移适配。

- 在网络恢复后，逐一比对设备上的推送服务、工作器、配置校验和事件引擎，均与仓库工作版本一致；重新运行 36 项隔离断言、编译和工作器集成测试，全部通过。
- 先保持开机启动关闭，设置临时回退，再分阶段启动、暂停和恢复服务。两段运行观察合计约三分钟，Wi-Fi 管理连接、LAN 状态、DHCP 服务和 VPN 均正常，未复现网络失联。
- 首段运行采样的整机 CPU 约 3%–7%，可用内存约 787–794 MiB；这是整机采样，不是对推送进程独立资源消耗的测量。
- 恢复后的真实测试通知取得 HTTP 200、飞书业务码 0，待发队列为零；服务运行状态和开机启动项均已回读确认。
- 推送未启动时、暂停后以及运行中均观察到当前欠压/降频标志。供电问题独立存在；本次没有证据证明推送造成此前断网，也不能据此确定此前断网的唯一原因。
- 本轮没有再次重启、拔电或进行长期行车测试，开机启动项启用不等于已经完成冷启动耐久验收。有线口保留 LAN，但复测时没有接线，未重新验收有线 DHCP。

磁盘镜像、原始日志、运行采样、实际配置和临时维修脚本仅保存在本地私密目录，不属于公开仓库内容。可写分区曾完成离线日志恢复；修复成功与网络恢复的先后关系不能单独证明故障根因。
