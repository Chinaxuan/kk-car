# 52Pi EP-0136 UPS Plus 电源管理

适用设备为树莓派 3B+、OpenWrt 25.12.5 和 52Pi EP-0136。连接 KK-Car 后访问 `http://192.168.88.1/cgi-bin/luci/admin/kkcar_ups`，使用原 LuCI 管理员登录。采集与低电监控都在树莓派上运行，不依赖电脑或手机常开。

## 页面能看到什么

主控在 I²C `0x17`，树莓派供电与电池侧 INA219 分别在 `0x40`、`0x45`，RTC 在 `0x68`。页面每 10 秒显示两路电池电压差、低电判断参考电压及来源、USB-C / Micro-USB 输入、UPS 输出、电池端与两颗传感器的电压、估算电流和功率、温度、电量估计、控制器固件版本和序列号、运行与充电时间、采样周期、来电自启、电池参数、关机与重启倒计时、RTC 时间，以及树莓派当前和本次启动曾出现的欠压、限频、降频、软温控。序列号只在已登录页面显示，不应放入公开截图、日志或仓库。

电流和功率由 INA219 原始压降与厂家示例代码中的采样电阻值推算；该板两颗 INA219 的校准寄存器为 0，数字**未经外部仪表校准**。正电池电流表示充电，负值表示放电。电量百分比由 UPS 估算，厂家要求至少完成一次完整充放电校准；不要据此直接推算剩余续航。厂商标注的强制温度保护为 65°C，本页从 50°C 起提示检查散热。I²C 不响应或原始帧出现不可能的固件版本、电压或运行计时时，最多重读两次，然后明确报错；不会把异常帧或旧值显示成实时数据。
电子纸顶栏会在尚未验证校准的百分比前显示 `~`，例如 `~85%`，提醒该数值只作粗略参考；安全关机始终按电压判断。

## 电压差异与放电测试准备

新增一致性检查：保留主控与 INA219 两个原始读数，同时返回 `voltage_reference`。两路均有效且相差超过 **150 mV** 时，低电参考回退主控，并提示传感器暂不用作低电判断；差异较小时继续使用 INA219。无有效读数时明确返回未知。150 mV 是软件的一致性检查界限，**不是厂家规定的放电截止电压，也不代表完成校准**。关闭策略后仍可看到参考来源，但不会因软件阈值触发关机。

本次实物万用表测量在满充附近与一次短放电后都更接近主控读数；尚未核对低压段。因此没有对 INA219 原始数值加固定偏移；下文 2026-09-27 记录了后来经明确授权进行的空电与保护参数设置。原始参数异常仍需独立排查，不能仅凭保护寄存器为 0 就断定硬件保护有效或无效。

下一轮测试按以下顺序：

1. 保持外部供电，结合电池实际电压、充电电流变化及温度确认充满；不只依赖百分比到 100%。
2. 根据电池完整型号核对厂家最低放电电压，并确认本板硬件保护行为，再选定人工结束条件。3.7V 是标称电压，不能直接作为最低截止依据。
3. 使用现有每分钟私有记录做受控放电，定期对照两节电池实际电压；先做分段测试，在确定的结束条件到达前接回外部输入，避免突然断电损伤 SD 卡。
4. 只有真实完整充放电及下一次读数验证完成后，才能评价容量学习、剩余电量或总续航。短测成功不能替代这些验收。

2026-09-26 的最新测试状态：约 16 分钟电池供电后人工接回外部输入，接回后确认充电及系统持续运行；此前临时使用的 3700 mV 软件策略已按用户要求关闭。下文较早记录中的“已启用”是历史状态，不能作为当前状态。公开代码仍默认关闭，并保留设备私有配置。

## 2026-09-27 保护电压与固件核对

硬件保护的新设置范围为 **2750–3900 mV**，下限来自本次已确认的电芯规格，不能作为其他电池的通用推荐。空电基准用于估算百分比，保护电压用于控制 UPS 输出；这两项与 Pi 软件正常关机阈值独立。当前设备按用户要求把空电基准、保护电压设为 2750 mV，两项分别读回确认，并恢复原来的自动参数模式。满电学习基准由固件自动维护，不强制覆盖；它也不能直接当作电池实测充电截止电压。软件低电关机仍为关闭，公开代码不自动启用此设备配置。

厂家公开的 [V9 固件源码与说明](https://github.com/geeekpi/upsplus/tree/main/firmware) 存在两处需留意的行为：保护变量为 0 时先回退到 3600 mV，因此 0 不能当成“关闭保护”指令；手动模式在百分比计算时将电压钳位至空电基准，再与保护值比较，空电与保护相等可能让保护不触发。后台因此拒绝新写入 0，只在自动模式允许两项相等；手动模式及启用手动模式时要求空电基准严格低于保护电压。V9 源码不能直接证明设备所装 V10 的全部行为，实际关断仍需实测。

实机设置前在外部供电下保存原始寄存器与模式到设备私有目录，临时启用手动模式写入空电值，再恢复自动模式并回读。最初尝试把满电基准设为 4200 mV 时，恢复自动模式后固件重新显示原学习值；该次操作已尝试恢复并回读，随后仅校验和调整用户指定的两项截止参数。未改 INA219 原始电压，没有恢复出厂、进入 OTA、重启 UPS 或启动新的放电测试。用于核对的万用表电压接近主控；另一组电压有明显偏差，仍保留原值并标记未校准。

当前实机固件版本为 10。官方 OTA 服务能返回与板子身份绑定的加密固件，但响应没有可确认的版本号，指定版本下载又返回 404；没有据此断言已是最新版，也没有执行升级。厂家仓库声明产品已结束维护，不能使用其他设备的固件包。固件二进制、身份、下载响应和原始测量只保存在私有目录，不随公开仓库发布。

修改寄存器后的读回只验证参数接受情况。**低压关断点、完整容量、电量百分比准确性、彻底断电后的参数保留，以及 Pi 正常关机链路尚未验收。** 测试前保持外部供电；下一轮需单独安排受控放电和人工结束条件。

## 可手动设置的项目

| 项目 | 页面行为 |
| --- | --- |
| 来电自启 | 保存后写入 UPS `0x19`，决定外部供电恢复后是否自动启动 |
| 采样周期 | 1–1440 分钟，写入后读回确认 |
| RTC 校时 | 将树莓派已经校准的 UTC 时间写入 RTC 并读回；不自动用 RTC 设置系统时间 |
| 低电安全关机 | 默认关闭。开启后仅在外部供电断开时监测电压，两路有效电压差不超过 150 mV 时使用电池侧 INA219 电压；传感器不可用或差异超过 150 mV 时回退 UPS 主控电池电压，并显示差异告警。连续 3 次低于设定阈值才安排 UPS 180 秒断电，并执行 OpenWrt 正常关机。阈值可设 3300–3900 mV，电量百分比不参与判断 |
| 满电、空电、保护电压与用户参数模式 | 高级设置，必须有外部供电，需输入确认文字，校验范围和电压关系后写入并读回。设备原始参数可能超出推荐的新设置范围，页面只显示原值，不会自动改写 |
| 重启树莓派 | 仅重启操作系统，UPS 持续供电 |
| 安全关机、UPS 电源循环重启 | 先设置 UPS 180 秒倒计时，再让 OpenWrt 正常停止；断电后远程页面会失联 |
| 取消倒计时 | 取消 UPS 内的关机或重启计时，不会撤销已经开始的操作系统关机 |
| 恢复 UPS 出厂参数 | 仅在外部供电时允许；先把当前寄存器值保存在设备私有目录，再发送重置指令。可能改变电池保护参数 |

除了取消倒计时，其余电源操作均需输入对应确认文字。页面和后台只允许操作上述已知寄存器，校验设备当前值以防覆盖并发修改。**固件 OTA 没有开放网页按钮**：厂家说明升级失败可能使 UPS 无法正常工作，必须单独核对固件版本和恢复条件。

默认的低电策略为关闭、阈值 3550 mV。页面中的「启用监控」只有点击「保存策略」才生效；策略私有文件为 `/etc/kk-car/private/ups-policy.json`，权限 0600。低电监控由 `kk-car-ups` 服务每 10 秒运行一次；读数失效、输入电源恢复或电压回升会清空连续低电计数。负载电压与 UPS 主控读数可能不同，设置阈值前应在实际电池、负载和供电接法下核对。UPS 自身的电池保护参数与这项软件关机策略是两回事。

## 安装与恢复

1. 按厂家方向安装 UPS、电池与支柱。电源只接 UPS 输入端，**不要同时给树莓派自身供电口输入电源**。
2. 备份 `/boot/config.txt`，启用 `dtparam=i2c_arm=on`，安装与固件匹配的 `i2c-tools`，重启后确认 `/dev/i2c-1` 与上述四个 I²C 地址。
3. 部署 `kk-car-ui/root/etc/kk-car/ups-read.uc`、`ups-control.uc`、`ups-watch.uc`、`ups-watch.sh`、`root/etc/init.d/kk-car-ups`、`kkups.uc`、LuCI 页面/样式、菜单和 ACL。脚本与 init 文件用 0755，其余代码 0644 且属于 root。启用 `kk-car-ups` 服务；初始策略仍为关闭。页面更新只重启 rpcd 或刷新浏览器，不必重启 network、无线、DHCP 或 VPN。
4. 打开页面核对 UPS 输入/输出、电池温度和树莓派供电标志，再确认热点、WAN 与 VPN 仍可用。将新增文件、`/boot/config.txt` 及私有策略路径加入升级保留清单；`i2c-tools` 软件包需另行记录。

页面读数异常时，在 SSH 中只读检查 `i2cdetect -y 1`、`ubus call kkups status`、`vcgencmd get_throttled`。要停用软件关机，先在页面关闭并保存策略，或停止 `kk-car-ups` 服务；这不会改变 UPS 硬件寄存器。若不再使用 I²C，恢复原 `/boot/config.txt` 后重启。断电时不要拔 SD 卡，先正常关机，再切断 UPS 输出。

## 实机验证边界

2026-09-26 排查一次「屏幕仍显示约 73% 却突然断电」：再次开机的启动日志提示 SD 卡启动分区上次未正常卸载；设备上的软件低电策略当时为关闭，不能据此确定 UPS 硬件断电的具体触发点。充电时电量估计在数秒内从 81% 跳到 90%，因此百分比不可用于设定关机时机。已在设备上启用私有的 3700 mV 软件低电策略和来电自启，监控读回 `external_power`，热点仍可访问；尚未进行真实低电触发和来电重启试验。这些设备设置不随公开源码部署自动启用。尝试把主控满电基准从 4288 mV 改为 4200 mV 时，写入后校验失败，读回仍为原值；未继续写空电、保护电压或用户参数模式。电池参数校准仍待查清固件写入行为及受控充放电测试。

已验证四个 I²C 地址、实时数据、断开充电输入后转由电池供电、树莓派输出电压和当前无欠压、采样周期 2→3→2 分钟写入/读回、RTC 从停振状态校时并读回、低电服务初始为关闭、非法设置被拒绝，以及桌面和 390px 页面布局。关机/重启、UPS 恢复出厂、真实低电触发与再次来电自启尚未做实机断电试验；页面提供控制，不应把这些操作视为已验收的可靠恢复链路。当前放电测试时间短，不能证明总续航或长期温度稳定。

寄存器与供电规则以 [52Pi 官方说明](https://wiki.52pi.com/index.php?title=EP-0136) 为准；电流估算依据 [52Pi 示例程序](https://github.com/geeekpi/upsplus/blob/main/upsplus.py) 与 [TI INA219 数据手册](https://www.ti.com/lit/ds/symlink/ina219.pdf)。

## 电池短时间关机与倒计时追溯

2026-09-26 增加 [持久故障记录](FAULT-LOG.md)，关机前保存触发电压和阈值。电池主控读数与负载传感器可能相差约 0.4V，当前设备的 3700 mV 软件策略偏保守，不能用未校准的百分比证明还有多少容量。记录一次电池供电中负载从约 3.78V 降至约 3.70V、主控仍约 4.09V；尚不能区分未充满、负载压降、电池容量/接触与阈值过高各自的影响。未经受控测试未下调阈值。

本次发现外部电源存在时仍残留 88 秒关机计时，已取消读回 0。watcher 新增启动时对遗留计时的核对及取消，不在正常运行时反复取消，也不取消电池供电下的保护计时。人工电源操作会留下本次开机意图，避免 service restart 误取消。真实重启/来电恢复未验收。
