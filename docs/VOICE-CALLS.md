# DJI 网页电话：现状、部署与恢复

本功能针对当前 Baiwang / QDC507 一代 DJI 4G 模块，是**试验性电话控制**。页面已能显示来电、发出拨号/接听/挂断指令，并尝试把模块 PCM 语音通过 USB 声卡和 HTTPS WebSocket 送到浏览器。**真实双向电话尚未成功**：多次接听约 12 秒后中断，双方无声；不能用作车内可靠电话或紧急联络。正常蜂窝上网、VPN 和短信不依赖语音服务。

## 当前实机证据

- 树莓派重启后，DJI 的 QMI 数据会话、USB 声卡、模块侧 `qdc507_voice` / `qdc507_aprv3` 临时驱动和 HTTPS 音频网关均可恢复；网页在受信任的 HTTPS 页面能打开并检测电话硬件。
- `AT+QCFG="ims"` 为 `1,1`，`volte/disable` 为 `0`，活动 MBN 为 `VoLTE_OPNMKT_CT`，IMS 数据上下文活动。这些只证明配置和数据上下文，**不是 IMS 语音注册或通话成功的证据**。该固件不支持测试过的 `AT+QIMSREG?` 查询。
- 网页接听曾使 `AT+CLCC` 显示语音通话活动，随后模块 USB 声卡采集报 I/O 错误，通话中断。为排除浏览器音频，另一次直接发送 `ATA`，完全不启动 PCM/USB 音频路由，通话仍在约 12 秒后中断。`AT+CEER` 返回 `0,25`；[Quectel 参考手册的原因表](https://forums.quectel.com/uploads/short-url/cBnrTmjnCg7OGnqRsk8dIpbHuVX.pdf)将其解释为“网络释放，未给出原因”，不能据此确定单一根因。
- 最近测试时蜂窝 SINR 约 −2 至 1 dB；树莓派同时报告当前欠压/降频 `0x50005`。这两项可能影响稳定性，但没有对照实验，不能宣称是通话失败的原因。
- 来电/未接事件进入已有飞书通知队列；至少一次真实来电事件取得 HTTP 200 和飞书业务码 0。现在每约 5 秒采样一次；短到采样间隔内的振铃仍可能漏报。网页接听会留下不含号码的短期标记，减少已接通却被误报“未接”的情况；这一修正已通过隔离测试，尚未在下一次真实来电中复测。

## 页面使用边界

1. 在已信任设备本地证书的浏览器中打开 `https://192.168.88.1/cgi-bin/luci/admin/kkcar_dji`，用原 OpenWrt 管理员身份登录，并仅在需要网页音频时授权麦克风。不要绕过浏览器的证书警告。
2. 页面「检测电话能力」的“硬件就绪”仅表示模块音频资源与控制命令可用，不代表双向通话已验收。拨号、接听、挂断按钮目前用于受控测试。
3. 飞书自定义机器人只发送**文字来电提醒**，不传输来电号码和声音。Webhook 不能把 SIM 语音桥接成飞书语音通话。飞书应用的电话加急是消息提醒，也不是实时通话桥；若未来要做实时转接，需要独立 SIP/媒体网关和飞书端明确支持的音视频接入能力，当前没有实现。

## 组件和部署

公开仓库包含 `kk-car-ui/voice-gateway/` 的 Go 源码、`dji-voice-*`、`module-voice-*`、rpcd 接口、浏览器 `voice-worklet.js` 和 LuCI 页面；**不包含**第三方内核模块/PCM 二进制、设备证书私钥、实际 SIM/运营商资料或语音记录。临时模块侧驱动文件只在树莓派私有 SD 目录中，开机后由 `kk-car-voice-runtime` 通过已授权的 root ADB 恢复到模块 `/tmp`。脚本固定校验三个二进制的 SHA-256 与模块内核 `3.18.44`；不匹配即停止，不自动刷写固件或更改 USB 组合。

实验依赖 [MaVo 源码版本 `0443dfd`](https://github.com/moluncn/mavo/commit/0443dfdaf8aec086fd76ba2ee9152fd908114524) 对应的模块侧运行组件。自行获取和核对其许可、来源及脚本中的哈希；不要把二进制或私有驱动打包进本公开仓库。主机还需 `adb`、`socat`、`flock`、ALSA 工具和受信任的本地 HTTPS 证书。可将 `voice-gateway` 编译为 Linux arm64 可执行文件，安装到 `/usr/bin/kk-car-voice-gateway`；证书和私钥只放在 `/etc/kk-car/private/voice.crt`、`voice.key`，目录限制为 root 访问。启用 `kk-car-voice-runtime` 与 `kk-car-voice-gateway` 后，先读回服务状态和 `voice_probe`，再检查原 Wi-Fi、QMI WAN、VPN 和短信。

音频网关默认只监听车内 LAN 的 `192.168.88.1:8443`，WebSocket 需要 LuCI 签发的短期一次性票据，且核对页面来源；它不在蜂窝 WAN 上开放。通过 VPN 管理地址打开页面时，当前网关不提供远程声音连接。证书信任需要在每台要通话的浏览器设备上单独配置；仅能查看普通页面不等于麦克风/音频可用。

停止实验功能可以分别停止并禁用 `kk-car-voice-gateway` 和 `kk-car-voice-runtime`，然后执行 `/etc/kk-car/dji-voice-route.sh stop` 清理临时模块路由。蜂窝 WAN、短信和 VPN 应继续运行。模块 root ADB 授权可能是持久的，停止这两个服务不等于撤销该授权；不要在没有单独核验的情况下声称设备恢复出厂状态。

下一步应先在更好信号和可验证的供电条件下重复“无音频路由接听”对照，再抓取模块 IMS 注册/释放诊断和 PCM 路由日志；只有通话能持续、双方可听且挂断/重启回退通过后，才可把网页电话标为可用。此前不要把 `AT+QPCMV`、VoHive 的 VoWiFi 路径或其他固件配置直接套到该模块。
