# DJI 一代 4G 模块接入 QMI

本次实机为 DJI 一代模块，识别信息为 `Baiwang / QDC507`，固件版本 `QDC507GLEFM21`。原固件已支持 QMI 数据连接；本次只调整 USB 设备标识并配置 OpenWrt，**没有刷写整套模块固件**。完成后由树莓派独立管理模块，不依赖 Mac、虚拟机或 Mac 上的常驻程序。

以下记录针对这只模块与 Raspberry Pi 3B+ / OpenWrt 25.12.5，不代表所有 DJI 模块、其他硬件版本或运营商均已验证。

## USB 模式与驱动

| 项目 | 本次实际设置 |
| --- | --- |
| 原 USB 标识 | `2ca3:4006` |
| 调整后 USB 标识 | `2c7c:0125` |
| USB 功能组合 | `1,1,1,1,1,0,0`，保留原组合 |
| 数据模式 | `usbnet=0`，保留 QMI |
| AT / 串口驱动 | `option` |
| 网络驱动 | `qmi_wwan` |
| 控制与网络节点 | 常见为 `/dev/cdc-wdm0`、`wwan0`，须按实际枚举核对 |

安装以下软件包；依赖由与当前固件匹配的软件源处理：

```sh
apk add kmod-usb-serial-option kmod-usb-net-qmi-wwan uqmi luci-proto-qmi socat
```

先读取并在本地私密备份中保存 `ATI`、`AT+QGMR`、`AT+QCFG="usbcfg"` 与 `AT+QCFG="usbnet"` 的结果。确认型号及原始组合与上述记录一致后，本次使用了以下 AT 操作：

```text
AT+QCFG="usbcfg",0x2c7c,0x0125,1,1,1,1,1,0,0
AT+QCFG="usbcfg"
AT+CFUN=1,1
```

先回读设备标识确认写入成功，再重启模块。重启后设备以标准标识重新枚举，由内核原生驱动识别。这里只重启 USB 模块，不是重刷固件，也不是把模块硬件型号变成 EC25。AT 端口必须从实际 USB 接口关系确认，不能假设始终是某个 `ttyUSB` 编号。

临时向驱动 `new_id` 写入通用匹配规则曾用于诊断，但重新插入时可能把串口接口错误绑定给 QMI 驱动，产生多余的 `cdc-wdm` / `wwan` 节点。**不能把这种通用动态绑定当作长期接入方案。** 本次状态采集还会检查 USB interface `04` 与控制、网络节点的对应关系，不按编号取第一个设备。

## OpenWrt 接入设置

下列是逻辑接口 `wan` 的最小配置示例，控制节点需替换为本机实际节点。`ctnet` 是本次中国电信 SIM 的实测 APN；其他 SIM 应向运营商核实，不能直接照用。

```uci
config interface 'wan'
        option proto 'qmi'
        option device '/dev/cdc-wdm0'
        option apn 'ctnet'
        option pdptype 'ip'
        option metric '20'
        option ipv6 '0'
        option delegate '0'
        option autoconnect '1'
        option dhcp '0'
        option peerdns '0'
```

`pdptype=ip` 请求 IPv4 数据会话；`dhcp=0` 使用 QMI 提供的地址配置。该示例不包含系统范围的 IPv6 关闭、DNS、VPN、转发或防火墙配置，必须与 KK-Car 已有规则一起核对。不要复制公开仓库的示例 VPN 地址覆盖设备真实配置。

**首次给正在运行的系统安装 QMI 软件包后，本次需要重启 netifd 才能加载新协议。** 安装后仅执行 `ifup wan` 时曾实际得到 `proto: none`，不能保证单独重新拉起 WAN 就足够。netifd 重启会影响现有网络，应先保存私密配置备份，确认本地控制台或其他可恢复管理方式，再安排维护；这不是以后每次刷新页面或更新采集器都要执行的步骤。

部署时保留 `wan` 这个逻辑接口名称，数据接口由运行时状态发现。QMI 可能直接在父接口提供地址，也可能经动态 `wan_4` 提供 IPv4 信息；控制节点路径不能当作网络接口名使用。WAN 防火墙区域与 NAT、策略路由都要验证覆盖实际 `wwan` 设备。

## 有线优先与管理保护

网口切换为 WAN 后，有线健康时仍优先使用有线出口；DJI 模块作为蜂窝出口。出口维护脚本读取实际接口、地址及网关，支持没有显式网关的默认路由以及 `/32` 蜂窝地址，避免固定写死 `eth1`。

切换前先部署并检查新增的出口模型及其调用文件，再安装覆盖 `eth*`、`wwan*`、`usb*` 的防泄漏规则，最后启用 QMI WAN。不要为了更换模块重置 LAN、Wi-Fi 或 DHCP 服务。防泄漏规则能阻止错误直出，但不能替代转发、NAT 与 VPN 的实测验收。

页面与历史流量按实际接口读取计数；更换数据来源时跳过一次速率计算，避免把新旧模块的累计流量差值显示成速度峰值。QMI 未提供或未成功读到的数据保持未知，例如运行时间、连接时长、频段与部分信号指标，不用推测值填满面板。采集成功不等于已建立互联网连接。

## 回退到原 CDC 上网棒

完整 UCI 配置及模块原始设置只保存在设备或本地私密备份，不上传仓库。回退时使用自己的备份恢复逻辑 `wan` 的 CDC / DHCP 配置，并核对当前物理接口；原设备曾使用 `eth1`，USB 重新枚举后不能盲目沿用。

典型 CDC WAN 的关键字段是 `proto=dhcp`、`device=实际网卡名`，需要移除 QMI 专用配置并保留原有 DNS、IPv6 与防火墙约定。先确认本地管理可达，再重新连接 WAN；不要把整个网络配置替换成来自其他设备的示例。F30A 的管理地址从实际 WAN 网关判断，不再只依赖固定的旧地址。

## 当前验证范围与边界

截至本次接入阶段，已实机验证：

- 原固件响应 AT 查询，支持 QMI；调整 USB 标识后重启模块，由原生驱动识别。
- SIM 可读取并注册中国电信 LTE 网络。
- 使用 `ctnet`、IPv4 与 QMI 获得运营商分配的私有 `10.x` 地址；真实地址不记录在公开文档中。
- 绑定 DJI 网卡的 Ping 3/3 响应，国内 HTTP 返回 200；fw4 的转发和 NAT 包含实际 QMI 接口。
- 实际临时停用有线 WAN 后自动选中 DJI，IKEv2 重建，公司探测目标 3/3 响应，约 30–36 ms；VPN 下国际 HTTPS 返回 204。
- 恢复有线后自动恢复有线优先，VPN 下国际 HTTPS 再次返回 204。该测试是逻辑接口停用/恢复，不是拔插整机或长期移动测试。
- IPv6 地址和路由为空、关闭及转发开关均符合 IPv4-only 策略。PBR 恢复 IPv4 转发时会同时打开 IPv6 转发标志，出口守护现在每轮检查并恢复项目策略。

GNSS 实际定位、eSIM 管理、真实短信收发尚未验收，不能据查询命令存在就宣称可用。2026-09-24 已增加 [DJI 独立控制页](DJI-CONTROL.md)，实机只读验收了短信仓占用和模块状态；短信读写只在模拟串口中验证。SIM 就绪、基站注册、获得地址、访问互联网和 VPN 通行是不同检查项。

本次设备仍有供电告警，尚不能宣称长期稳定或车载移动场景稳定。仅凭充电器标称总功率不能判断树莓派与 USB 模块端的供电是否正常；后续仍需在供电正常的条件下验证冷启动、重新插入、弱信号恢复与持续运行。
