# 网络守护：多目标检测与有限恢复

本轮借鉴 [ROOter 的连接监控](https://ofmodemsandmen.com/monitor.html) 思路，把多目标探测、连续轮数和恢复限额加入现有 OpenWrt。没有替换固件，也没有安装第二套选网服务。原有 `kk-car-uplink` 继续负责有线优先、4G 备用和出口路由。

## 查看与设置

连接 KK-Car 后，在顶部导航选择「网络守护」，或访问 `/cgi-bin/luci/admin/kkcar_health`。继续使用原有 LuCI 管理员登录。行车总览增加简短的出口 / VPN / DNS 状态与入口；各模块和设置中心也提供入口。

| 项目 | 默认设置 | 行为 |
| --- | --- | --- |
| 持续检测 | 开启 | 约每 30 秒检查一次，网页关闭后继续运行 |
| 物理上网目标 | `223.5.5.5`、`119.29.29.29` | 分别绑定已就绪的有线和蜂窝接口，不能无接口重试 |
| VPN 目标 | `10.8.8.8`、`1.1.1.1` | 绑定 `ikecar`；公司目标和公网目标都从隧道发出，不回落到物理 WAN |
| DNS | 本机解析 `www.baidu.com` | 只检查和记录，不修改 DNS 或重启 dnsmasq |
| 连续失败 | 3 轮 | 所有目标连续无响应才进入故障；单个目标失败为「部分目标无响应」，不触发恢复 |
| 恢复确认 | 2 轮 | 已判定故障后，需要连续成功 2 轮才重新显示正常 |
| 开机等待 | 120 秒 | 避免开机拨号过程触发自动恢复 |
| 重连冷却 | 300 秒 | 两次动作至少间隔 5 分钟 |
| 每小时动作限额 | 2 次 | VPN 和蜂窝共用预算，失败的指令也计入 |
| VPN 自动恢复 | 开启 | 物理出口正常、VPN 连续故障时，发起连接或重建 CHILD 数据隧道 |
| 4G 自动重新拨号 | 关闭 | 可手动开启，只对 DJI / QMI、可确认没有通话的场景生效 |

后台可调整检测间隔 30–300 秒、失败 3–10 轮、恢复 2–5 轮、冷却 300–3600 秒、每小时 1–4 次、开机等待 120–600 秒；每条线路配置 2–4 个不重复的 IPv4 单播地址。修改采用版本校验，另一页面已保存时拒绝覆盖。仅更改此功能的私有设置，不写网络 UCI。

## 故障分类与恢复顺序

- 有线口处于 LAN、没有网线、SIM 缺失或要求 PIN/PUK：显示原因，跳过自动重拨。
- 出口状态过期、接口读取失败、探测未完成：显示待确认，不当成连通或故障。
- VPN 已被手动暂停、蜂窝被手动停用：保持暂停。守护不会擅自启动已停止的 charon 服务。
- 物理出口有响应但 VPN 所有目标连续失败：未建隧道时先发起连接；已建隧道时重建 `kk-car-internet` CHILD，不重启整个 strongSwan 服务。
- 4G 是当前出口或当前没有出口、持续故障且可选重拨已开启：确认 netifd 没有正在初始化，模块无通话，才对逻辑 `wan` 执行 down / up。
- DNS 故障只记录；未通过探测的站点可能是禁止 ICMP，不等同于整条网络不可用。

操作前再读一次配置与接口，重新探测，并取得与手动网络操作相同的锁。热点/网口试用待确认、DJI 控制、其他服务操作、正在通话/来电或通话状态不明时暂缓重拨；出口变化后至少等待 90 秒。4G 自动重拨使用已有只读语音能力检查，不拨号、接听或改写模块设置。F30A 未具有可验证的通话检查时，不自动重拨。

**不自动重启整机、整个网络、Wi-Fi、DHCP、防火墙，也不切换 USB 电源、改变频段或写模块固件。** 网络守护停止或关闭检测后，已有网络继续运行。上下文、冷却与限额使用启动标识和单调运行时间；NTP 调整不会提前释放冷却。同一次开机内重启守护服务仍保留预算，新开机重新进入等待期。

动作日志的「指令已提交」只表示命令返回成功，仍需要后续探测验证，不能当成网络恢复。

## 数据与保存

- 实时缓存：`/tmp/kk-car-network-health.json`，带启动标识、运行时间、目标响应与延迟。服务过期时页面显示待确认，并保留上次数据。
- 每次状态变化、服务启动和恢复尝试：`/etc/kk-car/private/network-health/events.jsonl`，512 KiB 主文件 + 一份轮转，最多 1 MiB。页面显示最近 80 条，按记录顺序展示；硬断电留下的末尾残缺行会在下次追加时截去。
- 私有设置：同目录 `settings.json`；状态预算在 `/tmp/kk-car-network-health-state.json`。
- 原有每分钟故障记录另加当前网络守护的分类、连续轮数和响应目标数，不保存电话、端点、原始 AT 输出或认证数据。
- 私有目录 0700，配置、日志与缓存 0600。日志、实际目标设置和设备配置不得上传公开 GitHub。

## 增量部署与回退

需要设备已有 Python 3、`ping`、`nslookup`、ubus、strongSwan 及本项目现有出口选择。新增 `network_health.py`、`kk-car-network-health` init、`kkhealth.uc`、页面 JS/CSS，更新 LuCI 菜单/ACL、各页入口、设置中心服务白名单、`kkcar` 状态和诊断采集器。不要覆盖设备私有目录。

新增 init 和 Python 文件设置为 0755，前端/RPC 为 0644。已有 `/etc/kk-car/` 升级保留目录覆盖私有设置和日志；将新增 init、S96/K12 启动链接、`kkhealth.uc`、前端 JS/CSS 加入 `/etc/sysupgrade.conf`。

校验文件与 Python / ucode / JavaScript 语法后，刷新 rpcd 和 LuCI 资源缓存，重启诊断采集器；启用并启动 `kk-car-network-health`。无需重启网络、Wi-Fi、DHCP、防火墙、VPN 或整机。rpcd 刷新后管理员会话可能需要重新登录。

部署前在私有位置保存所改文件。需要回退时先停止、禁用 `kk-car-network-health`，恢复原文件与菜单/ACL，再刷新 rpcd。保留原日志和配置用于调查；不要恢复或改动 network / wireless / dhcp / firewall。
