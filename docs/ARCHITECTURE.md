# KK-Car 简易管理页

已部署地址：<http://192.168.88.1/cgi-bin/luci/admin/kkcar>。

这是实际安装在现有 OpenWrt 25.12.5 上的 LuCI 页面，不是静态演示。使用已有管理员登录，前端资源全部本地加载。原 LuCI 的高级管理入口保留。

## 功能

- 上网棒接口、VPN 隧道、热点连接数、地址、运行时间、温度、内存及欠压状态。
- 实时速率每 5 秒更新；后台记录流量、VPN 延迟与信号历史，支持 1 小时、1 天、30 天。累计计数来自接口，不是套餐计费流量。
- VPN 暂停、启动、重连；保存开机自动连接选项。
- 国内出口、VPN 出口、公司服务和国外 DNS 分别检测，并保留检测时间。
- 修改热点名称及密码，125 秒确认窗口（包含应用前的 4 秒等待），未确认恢复原配置；试用期间重启，启动脚本在网络启动前恢复。
- 频段选择：5GHz（信道 149 / VHT20）或 2.4GHz（信道 6 / HT20），均使用 20MHz，同样使用确认/回退流程。设备内置无线不能同时运行两种频段；首页读取实际工作频率与带宽。
- IPv6 状态读取所有接口的内核开关、转发开关、地址和路由；当前完全关闭树莓派 IPv6，含开机与接口重建后的持久化配置。
- F30A Pro ADB 状态：运营商、网络制式、信号格数、LTE RSRP、蜂窝连接状态/时长、设备运行时长、蜂窝接口累计流量。每 30 秒更新，支持手动刷新。
- 上网棒重连；高级网络、备份恢复和上网棒管理入口。
- 网口用途开关：LAN 与热点同网；WAN 使用 DHCP，有线互联网探测稳定后优先于 4G，故障后回到 4G。切换有确认、超时回退和开机回退。

套餐余量没有可靠来源，以运营商查询为准。当前支持一个有线 WAN 加一个 4G WAN，没有增加任意 VPN 参数编辑。

## 网口 LAN / WAN 与出口优先级

默认保留 LAN。在简易页“网口用途”选择用途、勾选通过 Wi-Fi 管理的说明并保存；125 秒内确认保留，否则恢复整个网络配置文件。网口试用过程中不要同时使用高级页改网络。断电后未确认的网络配置由 `kk-car-ui-recovery` 在 netifd 之前恢复。

WAN 模式从 `br-lan` 移出 `eth0`，启用 DHCP 接口 `kk_ethwan`；该接口加入 WAN 防火墙区，IPv6 与上级 DNS 自动接收均关闭。LAN 模式禁用该接口并把 `eth0` 放回桥；Wi-Fi 保持在 LAN。现有 4G `wan/eth1` 不改名。

`kk-car-uplink` 每 5 秒执行一轮状态检查。以太网的 DHCP 路由 metric 500 供绑定 eth0 的探测使用；223.5.5.5、119.29.29.29 任一响应即本轮通过，连续 3 轮通过优先使用有线，连续 2 轮失败回到 4G，物理断线在下一轮处理。探测耗时和 DHCP 获取会影响时长，不承诺固定秒数或不断连接。上级网段若与 192.168.88.0/24、上网棒 192.168.0.0/24 或当前 4G 子网重叠，则不选择有线。

国内直连和 IKE 控制流量仍使用 mark 0x10000，新增 priority 9990 → table 301，在 PBR 自有规则之前选择出口。有线优先时表 301 默认路由走 eth0，同时主表添加 metric 5 的有线默认路由；4G metric 为 20。有线失效后删除优先主路由，表 301 回到 eth1。表 301 保留不可达默认路由，modem 管理网段始终走 eth1。VPN 业务 mark 0x20000 → table 300 保持原样。为避免保留 WireGuard 配置的服务器专用路由影响 IKE 源地址选择，主表另维护 VPN 服务器 203.0.113.10/32 的 metric 5 路由，随所选出口切换；原 metric 20 路由保留。

出口改变且 VPN 本来运行时重新建立现有 IKEv2 隧道；已暂停的 VPN 不自动启动。两个物理 WAN 均覆盖国外业务和国外 DNS 防泄漏规则。网络检查改为使用当前选中的出口。当前未做连接迁移或带宽叠加，已有 TCP 会话可能需要重连。

部署配置由 `install-ethernet.uc` 写入现有 UCI；重复运行保留已选择的模式。源码附带当前中国地址集和防火墙保护规则，未来更新地址集时须同步维护该文件。

验证：`tests/ethernet-safety.py` 在隔离 UCI 中验证保存、接口移出/放回、互斥、超时及启动回退；`tests/uplink-routing.py` 在三个 Linux 网络命名空间中验证真实路由、绑定接口探测、优先级、防抖、线路恢复、断线、冲突及无出口阻断。真实树莓派已通过网页完成 LAN→WAN→LAN，Wi-Fi 管理、4G 备用、IPv6 关闭保持正常。没有连接真实有线上级，尚未验证真实有线出口下的 IKEv2 连接。

## ADB 与 IPv6

路由器安装 OpenWrt 软件源中的 `adb`，固定连接 `192.168.0.1:5555`。棒子是 Linux 3.4.110-rt140；读取 `nv get` 白名单字段及 `/proc/uptime`、`wan1` 收发计数，不读取短信、SIM 标识或密码，不改变棒子配置。原厂页面 `service.js` 的 `getSignalStrength` 使用同样的 `network_type/rssi/rscp/lte_rsrp` 字段。

`kk-car-modem` 为 procd 开机服务，后台只读采样并原子更新 `/tmp/kk-car-modem.json`，页面每 5 秒读取缓存。ADB 命令有超时限制，断开后自动重连；失败清空旧指标，超过 75 秒的缓存不作为当前数据显示。蜂窝接口流量可能因设备重启或驱动计数方式归零/变化，不当作计费流量。温度、RSRQ、SINR 和套餐余量没有验证来源，因此未展示。

IPv6 在 `/etc/sysctl.conf` 禁用内核协议、转发及自动配置；UCI 网络接口 `ipv6=0`，RA/DHCPv6/NDP/PBR IPv6 关闭，DNS 过滤 AAAA。`99-kk-car-ipv6` 在接口建立/更新后再次关闭全部接口的 IPv6。此状态指树莓派，不表示已更改上网棒的运营商 PDP 或手机自身的协议栈。

## 结构与权限

`root/` 下的文件按相同绝对路径安装到路由器。前端在 `www/luci-static/resources/view/kkcar/`，后台为 `usr/share/rpcd/ucode/kkcar.uc`。ACL 只声明状态读取和白名单操作，未给未登录会话增加任何权限。SSID 使用 UCI API 写入，不插入 shell 命令；密码不通过状态接口返回。

所有可变操作经过临时任务锁；前端防止重复提交，后端独立验证输入和冲突。热点更改前复制当前无线配置，文件权限 600。备份及试用标记在确认或回退后删除。启动恢复服务为 `kk-car-ui-recovery`，启动顺序 19（网络服务之前）。

更新文件后使用 `/etc/init.d/rpcd reload` 加载后台；不要随意重启 rpcd，否则已有网页登录可能失效。前端更新后刷新浏览器。

### 网络历史（2026-09-19）

流量和 VPN Ping 由路由器后台每 10 秒采集，按分钟保存，保留最近 30 天。首页使用两幅共用时间轴的图，分别显示 Mbps 与 ms；支持鼠标、触摸和键盘时间滑块查看具体记录。

| 范围 | 图表汇总 | 页面自动读取 |
| --- | --- | --- |
| 最近 1 小时 | 每分钟 | 30 秒 |
| 最近 1 天 | 每 5 分钟 | 60 秒 |
| 最近 30 天 | 每小时 | 5 分钟 |

速度按有效采样时长加权；延迟按成功响应数加权，最小/最大延迟和发送/接收包数同时保留。接口切换、计数归零或重启时不计算跨越边界的速度。未响应保留空值，不作零延迟；未采集时段留空。历史从启用后开始，没有补造过去的数据。

`history.uc` 和 `history-write.uc` 由现有 Ping 服务调用，不另开常驻大进程。RAM 缓存位于 `/tmp/kk-car-history.json`，每天的分钟记录位于 `/etc/kk-car/history/<UTC日编号>.jsonl`，小时汇总位于同目录 `*.hours.json`。页面显示浏览器本地日期和时间。第一条完整分钟记录立即保存，之后每 5 分钟批量追加，突然断电可能丢失最近约 6 分钟。历史文件不含认证信息，但只允许管理员查看。磁盘保存失败在图表说明中提示。

30 天全量夹具共 43201 个分钟点约占 2.7 MB，读取 721 个小时点实测约 2.25 秒。每个日文件限制 512 KiB，过期日期自动清理。不能手工删除小时汇总后期待旧月份仍然完整显示；可通过模块的 `rebuild_hours(disk,day)` 从对应分钟文件重建。

## 本次同时修复的 DNS 问题

## 升级与移除

页面文件、菜单、ACL、后台、任务脚本、启动恢复脚本、ADB 采集服务、IPv6 热插拔脚本和服务启动链接均加入 `/etc/sysupgrade.conf`。整机配置备份包含认证资料，需私密保存。配置备份不含所有软件包；重刷系统后仍需安装所需 LuCI、rpcd ucode、strongSwan、PBR、curl、adb、nftables 及内核模块。

## ChatGPT / Gemini 地区检查

设备本地 `kk-car-auto-check` 每 600 秒通过 `kkcar.action` 检查六项，点击「检查网络」也可立即执行。自动与手动复用原任务锁；服务用单调运行时间计时，校时不会造成连续重复检查。忙碌后 15 秒重试，RPC 故障后 60 秒重试。`diagnostics_auto` 含运行心跳与下次预计时间，前端仅在心跳 45 秒内更新时显示自动检查启用。六项检查中，新增两项均由树莓派经 `ikecar` VPN 使用 IPv4 发出，不携带账号、Cookie 或 API 密钥。每项最长 12 秒；Gemini 页面上限 1.5 MiB，ChatGPT trace 上限 32 KiB，仅保存归纳结果在内存，原始页面检查结束即删除。

- ChatGPT：读取 `https://chatgpt.com/cdn-cgi/trace` 的 `loc`，同时校验 `h=chatgpt.com`。这是该域名的 Cloudflare 边缘地区，不是 OpenAI 账号地区或完整模型可用性检测。
- Gemini：读取 `https://gemini.google.com/` 返回页面的 `vXmutd` 内部地区字段。当前实测 `JP`，同页另有 `JPN`；界面明确标为「页面地区（参考）」。此字段不是公开稳定 API，格式缺失或变化时显示地区未知。
- CN 表示中国大陆；HK、MO、TW 单独显示原始地区码。`非 CN` 仅指本次网络地区信号不为 CN，不代表该国家受到服务支持，更不保证账号能登录或模型能调用。
- 403 / 429、人机验证、重定向、超时、超大响应或无法解析，都不会判为中国或直接判为可用。实际终端的账号、定位及独立代理可能影响最终体验。
- 网络四项与地区两项分开计数；检查时间对应本次结果。不自动后台轮询 AI 网站。20 项隔离测试覆盖地区、失效格式、验证码/HTTP 错误、超时、语言误判等场景。
