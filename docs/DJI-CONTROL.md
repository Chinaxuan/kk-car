# DJI 4G 模块控制页

连接 KK-Car 后，用原 OpenWrt 管理员账号打开 `http://192.168.88.1/cgi-bin/luci/admin/kkcar_dji`。这是独立于网络总览的模块页面；手机也可使用。当前适配对象是已转为 QMI 网络接口的 DJI 一代模块（Baiwang / QDC507），不是所有 DJI 蜂窝产品。页面和服务运行在树莓派 OpenWrt 上，Mac 不需要常驻；DJI 棒子只负责蜂窝通信，不能在它内部安装这套网页。

## 已接入的能力

| 页面功能 | 数据或操作来源 | 使用边界 |
| --- | --- | --- |
| SIM、注册、运营商和数据会话 | QMI 状态缓存 | 注册、取得 IP 与实际访问分别判定 |
| RSRP、RSRQ、SINR、RSSI 与收发流量 | QMI 与实际 `wwan` 网卡 | 信号约 30 秒更新；接口字节数不是运营商账单 |
| 频段、固件、模块温度 | 模块 AT 只读查询 | 频段只展示白名单字段；温度为 `AT+QTEMP` 第一值，即基带芯片温度 |
| SIM 锁状态与邻区信号 | `AT+CPIN?` 和 `AT+QENG="neighbourcell"` | 邻区只汇总同频/异频数量与最强 RSRP，不保存 Cell ID、PCI、TAC 或原始应答；不提供输入 PIN/PUK |
| 刷新状态 | 重新采集 QMI、AT 与短信仓占用 | 不重启网络、Wi-Fi 或 VPN |
| 重连 DJI 数据网络 | 仅重启 QMI `wan` 逻辑接口 | 使用蜂窝时会短暂中断上网与 VPN；不改 LAN、热点、路由配置 |
| 短信仓占用 | `AT+CPMS?` | 当前选用 SIM `SM` 作为读取、写入和接收仓；空间 40 条，满仓时新短信可能无法接收 |
| 短信中心：列表搜索和会话详情 | 用户点击后查询 | 按 8/16 位分段标识、发送方和日期合并长短信；缺段明确标出，不猜测正文；读取可能把未读短信标为已读 |
| 发送和删除短信 | 用户填写并确认后执行 | 发送可能产生费用；删除长短信会逐段进行，可能部分成功；没有自动清理 |
| 新短信飞书转发 | 独立后台每 30 秒查询模块、收齐长短信后发送 | 只发启用后的新短信到已启用的地址；历史短信不补发；失败时保留在模块并重试 |
| 加密短信备份 | 路由器只持有公开证书，完整短信按会话加密至 SD 卡 | 解密私钥必须离线保存；不把明文、号码或密钥传到 GitHub |
| 电话能力检测 | 只读 `AT+QCFG`、`AT+CLCC` 和 USB 接口检查 | 只说明配置与硬件状态，不拨号、不改 IMS/USB，也不等于语音可用 |

当前新短信优先保存在 SIM 的 `SM` 存储区；树莓派运行且连接模块时，每 30 秒读取完整短信，把密文存入 `/etc/kk-car/private/sms-archive/`。旧短信曾分别存在模块 `ME` 和 SIM `SM`，清理前都已在 Mac 与 SD 卡核验加密快照。`dji-sms-forward-state.json` 只保存加盐指纹与各地址投递标记。明文发送请求、串口回复和飞书请求文件只短暂存在权限受限的 `/tmp` 内存盘。开启飞书短信事件后，号码和正文会进入对应飞书群，请按群成员权限管理验证码。已存入 SIM 的短信会随卡保存；模块断电时不能接收新短信。`SM` 选择在当前实机已读回确认，但拔插或断电后是否仍把新短信存入 SIM 尚未做物理验收；树莓派重新连接后会再次选择 `SM`。

## 与 VoHive 的关系

[VoHive 的 DJI 教程](https://github.com/wlzh/dji-4g-vohive-mac)将管理程序装在 Linux 虚拟机或其他 Linux 主机上，USB 模块只作为被管理设备；Mac 主要用来运行虚拟机，不是模块的存储位置。KK-Car 直接使用已经运行 OpenWrt 的树莓派承载自己的 LuCI 页面和短信服务，不需要再让 Mac 或虚拟机常驻，也没有安装 VoHive 二进制。[原作者仓库](https://github.com/iniwex5/vohive-release)已公告无限期停止维护；下面是按当前硬件和车载需求做的功能对照，不代表两个程序互相兼容。

| VoHive 方向 | KK-Car 当前状态 | 边界 |
| --- | --- | --- |
| 模组发现、SIM、信号、网络与流量 | 已接入 DJI QMI 与只读 AT 数据 | 只管理当前这只 DJI，不做多模组编排 |
| 短信中心 | 已接入长短信合并、搜索、详情、发送、逐段删除和加密备份 | 缺段不补造；不会自动删除模块原件 |
| IP 轮换 / 重连 | 提供 QMI 数据连接重连 | 重连会短暂断网，不保证运营商分配新公网 IP |
| 通知机器人 | 系统事件与新短信正文分别由后台服务发送 | 短信有独立事件开关，沿用三个地址的独立启停；历史不补发 |
| eSIM / 多卡 | 当前实体 SIM 和单模块，未接入 | 本模块 eSIM 查询命令返回错误；不能据此保证外接 eUICC 卡可用 |
| SOCKS5 / HTTP 代理池 | 未启用 | 当前路由器已通过出口选择和 VPN 管理上网；代理池需另行设计和隔离 |
| SIM 电话、USSD、任意 AT 指令和 VoWiFi | 电话目前只读检测，其他未开放 | 当前实机 USB 语音位关闭、IMS 配置为 0、USB 声卡未枚举；仅通话查询有响应，无法证明双向语音可用 |

更多对标： [DJ 4G Hub](https://github.com/WongLoki/DJ4Hub) 的 macOS 客户端提供短信、SIM 电话、eSIM、SQLite 历史和云盘备份，但作者将音频标为部分实验，电脑双向音频需要特定 USB 声卡和模块运行时；[ModemDeck](https://github.com/human-agent65535/ModemDeck) 在 Linux 上提供多线路短信、电话、录音和代理，默认接管模组并依赖 Docker/ModemManager，不能与当前 OpenWrt QMI 管理直接并行；[Mac 4G](https://github.com/HD838A/dji-4g-mac) 面向 macOS，支持短信、Webhook/Telegram/Bark 通知与 ECM 上网，明确不支持语音；[ModemManager](https://modemmanager.org/) 可在 OpenWrt 上管理蜂窝数据和语音，但改用它需要重新设计现有 QMI 接口所有权。对标的是能力，不代表软件已在这台树莓派安装或实测兼容。

VoHive 教程的 `/vocall` 是受限运营商条件下的 VoWiFi 模拟外呼，并非插上中国电信卡就有普通 SIM 双向电话。当前模块的音频接口和 IMS 状态均不满足直接开放电话按钮的条件；强制改 USB 组合或刷通用 EG25 固件可能使现有蜂窝 WAN 中断，不能把别人的演示直接套用到本设备。

## 尚未开放的功能

模块响应 GNSS 状态命令，但实际天线和定位尚未验收。当前保持 GNSS 关闭，页面仅显示状态，不开放启动按钮或记录轨迹。只有可靠备用上网链路、定位天线和停车测试条件齐备后，才能验证首次定位、持续速度与断电恢复。eSIM 查询指令在这只模块上返回错误；页面不提供 eSIM 设置。也未做频段锁定、运营商强制切换或固件刷写，这些操作可能显著降低移动中的联网成功率。

短信发送仍只在模拟串口中验证，不视为实机短信发送成功。2026-09-24 已分别为原模块 `ME` 的 23 个片段和 SIM `SM` 的 40 个片段生成加密快照、在 Mac 解密核验并比对 SD 副本，随后按备份身份逐条清理；清理期间刚收到的 1 条新短信被保留在 `ME`，由树莓派加密归档并得到飞书机器人成功回复。SIM 当前 `SM` 为 0/40，作为以后新短信的接收仓；模块 `ME` 留有该过渡短信。新短信不自动从 SIM 删除，SIM 将来仍可能满，需要定期核查占用并在确认备份后清理。日后飞书发送超时，可能已送达但本地未获确认，重试可能重复。模块满仓不会因为树莓派 SD 扩容而自动腾出空间。

## 故障判断

页面显示“模块未连通”时，先到网络总览确认 USB 识别、SIM、QMI 数据会话和当前出口。短信中心只显示数量时，先点“读取短信列表”，再点列表中的一条读取正文；如果还是旧版逐行小按钮布局，请重新加载页面资源。短信操作显示“忙碌”时，等待 AT 状态采样或上一项短信操作结束再试。短信“发送结果未确认”不能直接视为失败，避免立即重复发送。定位栏显示“未验收”不代表模块保证有可用 GNSS 天线。
