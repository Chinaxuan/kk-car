# DJI 4G 模块控制页

连接 KK-Car 后，用原 OpenWrt 管理员账号打开 `https://192.168.88.1/cgi-bin/luci/admin/kkcar_dji`。这是独立于网络总览的模块页面；手机也可使用。首次使用网页电话时，浏览器必须信任设备的本地 HTTPS 证书；不要跳过证书警告。当前适配对象是已转为 QMI 网络接口的 DJI 一代模块（Baiwang / QDC507），不是所有 DJI 蜂窝产品。页面和服务运行在树莓派 OpenWrt 上，Mac 不需要常驻；DJI 棒子只负责蜂窝通信，不能在它内部安装这套网页。

## 已接入的能力

| 页面功能 | 数据或操作来源 | 使用边界 |
| --- | --- | --- |
| SIM、注册、运营商和数据会话 | QMI 状态缓存 | 注册、取得 IP 与实际访问分别判定 |
| RSRP、RSRQ、SINR、RSSI 与收发流量 | QMI、AT 与实际 `wwan` 网卡 | SINR 取模块 AT 原始读数，不把 QMI SNR 冒充为 SINR；接口字节数不是运营商账单 |
| 频段、固件、模块温度 | 模块 AT 只读查询 | 频段只展示白名单字段；温度为 `AT+QTEMP` 第一值，即基带芯片温度 |
| SIM 锁状态与邻区信号 | `AT+CPIN?` 和 `AT+QENG="neighbourcell"` | 邻区只汇总同频/异频数量与最强 RSRP，不保存 Cell ID、PCI、TAC 或原始应答；不提供输入 PIN/PUK |
| 刷新状态 | 重新采集 QMI、AT 与短信仓占用 | 不重启网络、Wi-Fi 或 VPN |
| 重连 DJI 数据网络 | 仅重启 QMI `wan` 逻辑接口 | 使用蜂窝时会短暂中断上网与 VPN；不改 LAN、热点、路由配置 |
| 短信仓占用 | `AT+CPMS?` | 当前选用 SIM `SM` 作为读取、写入和接收仓；空间 40 条，满仓时新短信可能无法接收 |
| 短信中心：列表搜索和会话详情 | 打开页面及之后每 30 秒自动读取目录；正文仍需点击 | 未读优先、再按时间倒序；按 8/16 位分段标识、发送方和日期合并长短信；缺段明确标出；目录/详情读取可能把未读短信标为已读 |
| 回复、发送和删除短信 | 回复只预填原号码；用户填写并确认后才发送 | 发送可能产生费用；删除长短信会逐段进行，可能部分成功；没有自动清理 |
| 新短信飞书转发 | 独立后台每 30 秒查询模块、收齐长短信后发送 | 只发启用后的新短信到已启用的地址；历史短信不补发；失败时保留在模块并重试 |
| 加密短信备份 | 路由器只持有公开证书，完整短信按会话加密至 SD 卡 | 解密私钥必须离线保存；不把明文、号码或密钥传到 GitHub |
| 网页电话 | `AT+CLCC` 状态、`ATD`/`ATA`/`ATH` 控制，接通后模块 PCM→USB 声卡→HTTPS WebSocket→浏览器音频 | 一次 15–30 秒真实来电已确认双向有声；长时、移动和出站通话未验收，详情见 [电话验证与限制](VOICE-CALLS.md) |
| 定位开关、位置与速度 | `AT+QGPS?`、`AT+QGPS=1`、`AT+QGPSLOC=2`、`AT+QGPSEND` | 用户手动启动；每 30 秒只在页面内读取，不自动存轨迹；只有返回合规经纬度和 fix 才显示位置 |
| 设备流量统计 | 每约 30 秒读取 DJI 网卡收发字节，5 分钟写入一次 SD 卡 | 显示今日、本月、本机累计；网卡重连/计数归零时跳过断点，断电可能丢失最近约 5 分钟 |
| 套餐流量校正 | 选择运营商、短信号码、指令与每日查询时间，接收完整回复后解析 | 只在唯一识别“国内通用流量”的已用和剩余时校正；不把定向流量误算为通用流量 |

## 流量统计与每日校正

当前实机为中国电信，已用 `10001` / `108` 收到完整的 4 段查询回复，页面识别其中的“国内上网可使用流量”，把“专属定向”套餐排除在校正之外。设备保存最近一次运营商报告的已用、剩余与时间；页面的“套餐剩余·估算”在该报告基础上减去此后树莓派网卡新增的收发字节。运营商计费口径与网卡口径不完全相同，而且同一 SIM 若在别处使用，本机无法观察，因此估算值不能替代实时账单。切换网卡、首次部署与设备断电之间的流量可能没有完整记录；今日/本月统计从启用此功能开始，不追填历史。

当前实机已设为每天 09:00 查询一次；新安装时自动查询默认关闭，需按本卡运营商核对指令后启用。若定时时间模块不可用，服务在当天后续轮询时尝试。定时发送在本地留下当天已尝试的记录，避免重启后重复发送；管理员也可点击“现在查询并校正”，两次手动查询至少间隔 5 分钟。查询指令可能产生短信费用。电信示例指令参考 [中国电信广东短信服务](https://m.gd.189.cn/gd/sms/)；中国移动与联通可在页面选择并修改号码/指令，但各地套餐指令与回复格式不同，当前只对本机电信回复做过实测。若回复不含唯一可识别的国内通用已用和剩余，页面显示解析失败，保留上次有效校正。运营商回复正文继续由原短信加密归档和飞书开关处理；流量统计文件只存解析后的数字，不存原短信或号码。

实机 `AT+CLCC` 还会报告两个 mode=1 数据会话，页面只把 mode=0 当成语音电话。模块已开启 USB 语音位和 IMS 配置，USB 双向声卡已枚举。先前多次接听约 12 秒后释放、双方无声；后来确认 OpenWrt 的 BusyBox 不支持脚本里的小数秒 `sleep`，语音路由等待因此提前退出。修复后一次网页来电保持约 15–30 秒、双方有声，由用户主动挂断。当前只能确认短时双向通话；长期可靠性、重复来电、出站拨号和车内移动场景仍待验收。网页与飞书的来电提醒可用。

信号卡片采用便于现场判断的经验阈值，不是运营商保证值。RSRP 优 ≥−85、可用 ≥−95、弱 ≥−105、差 <−105 dBm；RSRQ 优 ≥−10、可用 ≥−15、弱 ≥−20、差 <−20 dB；SINR 优 ≥20、可用 ≥10、弱 ≥3、差 <3 dB；RSSI 强 ≥−70、一般 ≥−80、弱 ≥−90、差 <−90 dBm。由高到低依次判断，页面用不同颜色显示；RSSI 包含干扰与噪声，不能单独预测网速或丢包。

当前新短信优先保存在 SIM 的 `SM` 存储区；树莓派运行且连接模块时，每 30 秒读取完整短信，把密文存入 `/etc/kk-car/private/sms-archive/`。旧短信曾分别存在模块 `ME` 和 SIM `SM`，清理前都已在 Mac 与 SD 卡核验加密快照。`dji-sms-forward-state.json` 只保存加盐指纹与各地址投递标记。明文发送请求、串口回复和飞书请求文件只短暂存在权限受限的 `/tmp` 内存盘。开启飞书短信事件后，号码和正文会进入对应飞书群，请按群成员权限管理验证码。已存入 SIM 的短信会随卡保存；模块断电时不能接收新短信。`SM` 选择在当前实机已读回确认，但拔插或断电后是否仍把新短信存入 SIM 尚未做物理验收；树莓派重新连接后会再次选择 `SM`。

## 与 VoHive 的关系

[VoHive 的 DJI 教程](https://github.com/wlzh/dji-4g-vohive-mac)将管理程序装在 Linux 虚拟机或其他 Linux 主机上，USB 模块只作为被管理设备；Mac 主要用来运行虚拟机，不是模块的存储位置。KK-Car 直接使用已经运行 OpenWrt 的树莓派承载自己的 LuCI 页面和短信服务，不需要再让 Mac 或虚拟机常驻，也没有安装 VoHive 二进制。[原作者仓库](https://github.com/iniwex5/vohive-release)已公告无限期停止维护；下面是按当前硬件和车载需求做的功能对照，不代表两个程序互相兼容。

| VoHive 方向 | KK-Car 当前状态 | 边界 |
| --- | --- | --- |
| 模组发现、SIM、信号、网络与流量 | 已接入 DJI QMI 与只读 AT 数据 | 只管理当前这只 DJI，不做多模组编排 |
| 短信中心 | 已接入自动更新、未读优先、长短信合并、详情、回复预填、发送、逐段删除和加密备份 | 缺段不补造；不会自动删除模块原件 |
| IP 轮换 / 重连 | 提供 QMI 数据连接重连 | 重连会短暂断网，不保证运营商分配新公网 IP |
| 通知机器人 | 系统事件与新短信正文分别由后台服务发送 | 短信有独立事件开关，沿用三个地址的独立启停；历史不补发 |
| eSIM / 多卡 | 当前实体 SIM 和单模块，未接入 | 本模块 eSIM 查询命令返回错误；不能据此保证外接 eUICC 卡可用 |
| SOCKS5 / HTTP 代理池 | 未启用 | 当前路由器已通过出口选择和 VPN 管理上网；代理池需另行设计和隔离 |
| SIM 电话、USSD、任意 AT 指令和 VoWiFi | 试验性网页拨号、接听、挂断和来电提醒已接入；其余未开放 | 真实电话会中断且双方无声；USB 音频接口出现不代表 VoLTE 通话已经稳定。VoHive 的 VoWiFi/SIP 方案并非本模块的现成替代路径 |
| GNSS 位置与速度 | 手动启停、查询定位状态，只有真实 fix 才显示数值 | 当前实机可启动并停止 GNSS，但短时测试未获得定位；缺少天线/卫星验收，不声称可用轨迹 |

更多对标： [DJ 4G Hub](https://github.com/WongLoki/DJ4Hub) 的 macOS 客户端提供短信、SIM 电话、eSIM、SQLite 历史和云盘备份，但作者将音频标为部分实验，电脑双向音频需要特定 USB 声卡和模块运行时；[ModemDeck](https://github.com/human-agent65535/ModemDeck) 在 Linux 上提供多线路短信、电话、录音和代理，默认接管模组并依赖 Docker/ModemManager，不能与当前 OpenWrt QMI 管理直接并行；[Mac 4G](https://github.com/HD838A/dji-4g-mac) 面向 macOS，支持短信、Webhook/Telegram/Bark 通知与 ECM 上网，明确不支持语音；[ModemManager](https://modemmanager.org/) 可在 OpenWrt 上管理蜂窝数据和语音，但改用它需要重新设计现有 QMI 接口所有权。对标的是能力，不代表软件已在这台树莓派安装或实测兼容。

VoHive 教程的 `/vocall` 是受限运营商条件下的 VoWiFi 模拟外呼，并非插上中国电信卡就有普通 SIM 双向电话。当前模块虽已具备控制和 USB 音频资源，仍未完成稳定接通与双向语音。强制改 USB 组合或刷通用 EG25 固件可能使现有蜂窝 WAN 中断，不能把别人的演示直接套用到本设备。

## 尚未开放的功能

模块已能在不重启网络的情况下启动、查询和停止 GNSS；短时实机测试没有定位 fix，测试后已恢复关闭。页面允许手动操作，但只有取得卫星定位后才展示坐标、速度、卫星数与 HDOP。实际 GNSS 天线、车内遮挡、首次锁定和断电恢复尚未验收，不自动记录轨迹。eSIM 查询指令在这只模块上返回错误；页面不提供 eSIM 设置。也未做频段锁定、运营商强制切换或固件刷写，这些操作可能显著降低移动中的联网成功率。

2026-09-24 已分别为原模块 `ME` 的 23 个片段和 SIM `SM` 的 40 个片段生成加密快照、在 Mac 解密核验并比对 SD 副本，随后按备份身份逐条清理；清理期间刚收到的 1 条新短信被保留在 `ME`，由树莓派加密归档并得到飞书机器人成功回复。此后实机向电信客服号发送一次流量查询短信，收到并合并 4 段回复；这验证了向该客服号的收发链路，不代表任意号码的送达保证。SIM 新短信不自动删除，仍需在确认备份后人工清理。飞书发送超时可能已送达而本地未获确认，重试可能重复。模块满仓不会因为树莓派 SD 扩容而自动腾出空间。

## 故障判断

页面显示“模块未连通”时，先到网络总览确认 USB 识别、SIM、QMI 数据会话和当前出口。短信列表在页面载入后自动读取；若暂时失败，可点“刷新短信”，再点具体会话读取正文。短信操作显示“忙碌”时，等待 AT 状态采样或上一项短信操作结束再试。短信“发送结果未确认”不能直接视为失败，避免立即重复发送。流量校正显示“回复无法识别”时，核对本卡运营商及查询指令；后台不会用模糊匹配覆盖上一次有效值。定位显示“等待卫星定位”时，把模块置于开阔处并确认 GNSS 天线，不能用 4G 信号强度代替卫星信号判断。

接入过程和 QMI 回退见 [DJI 4G / QMI 接入](DJI-QMI.md)，整体部署顺序见 [部署与更新](DEPLOYMENT.md)。
